# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Read `AGENTS.md` first: it holds the project rules (Expo docs-first policy, Expo Router conventions, EAS usage, CNG rules) and is authoritative. This file adds commands and architecture notes on top of it.

## Product

Glidy is a group-travel app (site: glidy.app, owned by the user): a leader creates a session, invites friends by link/QR/code, sets a destination, and everyone sees each other's live location plus a shared turn-by-turn route. Routes can be saved, reversed for the trip home, and shared. Location is only read/shared while a session screen is open; users can pause sharing or blur their position. Visual style references the green/yellow "waypath" mock (soft cards, pill buttons, black pill tab bar).

## Stack

Expo SDK 58 / React Native 0.88 / React 19.3 / TypeScript 6 (strict), Expo Router with typed routes, React Compiler enabled (its ESLint rules are on: no `setState` inside effects, derive state instead). Native-only features (Google Maps, camera, background-capable location) need a **development build**, not Expo Go.

## Commands

The lockfile is `pnpm-lock.yaml`, so use `pnpm`. Add Expo/native packages with `npx expo install <pkg>`.

```bash
pnpm start              # Metro dev server (open the installed dev build)
pnpm ios | android      # expo run:* : build + install a dev build (needed after native deps/app.json changes)
pnpm lint               # expo lint
npx tsc --noEmit        # typecheck
```

There is no test framework. `ios/` and `android/` are generated (CNG, gitignored): after adding a native module or editing `app.json`, run `npx expo prebuild --clean` then `pnpm ios`/`pnpm android`.

Environment quirks on this machine:
- CocoaPods crashes with `ASCII-8BIT` unless `LANG=en_US.UTF-8` is exported.
- The system JDK is 23; Android builds need Android Studio's JDK: `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.
- After restarting an Android emulator, re-run `adb reverse tcp:8081 tcp:8081`.
- Two iOS simulators share the name "iPhone 18 Pro Max"; pass the UDID to `--device`.

`pnpm reset-project` is the starter template's destructive reset (moves/deletes `src/`); never run it.

## Configuration (demo mode vs real)

Copy `.env.example` to `.env.local` (gitignored); restart Metro after changes. All values are `EXPO_PUBLIC_*`.
- `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: real backend. Run `supabase/schema.sql` in the Supabase SQL editor first, and turn **off** "Allow public access" in Realtime settings (live locations use private broadcast channels).
- `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY`: the Google Maps Platform key for the native map, place search (Places API New), routes (Routes API) and pin naming (Geocoding). Enable Maps SDK for iOS and Android, Places API (New), Routes API and Geocoding API; restrict the key and set a budget alert and quotas in Google Cloud. `app.config.js` reads it and adds the `react-native-maps` config plugin, which bakes it into the native projects: after adding or changing it run `npx expo prebuild --clean` and rebuild the dev client.
- Without them the app runs in **demo mode**: on-device mock backend with two simulated travellers, a built-in list of demo places, straight-line routes, and a tile-free schematic map. Check `backend.isMock` / `hasMaps` rather than assuming real services.

## Architecture

- **Routing** (`src/app/`): root `_layout.tsx` wraps `AuthProvider` and uses `Stack.Protected` to switch between `(auth)` (welcome/login/sign-up) and `(app)`. `(app)/(tabs)` is a `NativeTabs` layout (Home, Routes, Profile); `(app)/session/*`, `join/*`, `routes/*` are pushed screens/modals declared in `(app)/_layout.tsx`. Deep links: `glidyapp://join/CODE`, `glidyapp://routes/ID` (a link opened while logged out is not preserved).
- **Backend abstraction** (`src/lib/backend/`): everything goes through the `Backend` interface in `src/lib/types.ts` (auth, sessions, routes, realtime channel). `index.ts` picks `supabase-backend.ts` when Supabase env vars exist, else `mock-backend.ts` (state in the expo-sqlite localStorage polyfill via `src/lib/storage.ts`). Add new data operations to the interface and both implementations. Row-level security, the `join_session` RPC, and realtime channel policies live in `supabase/schema.sql`; keep it in sync with `supabase-backend.ts`.
- **Live sessions**: `hooks/use-session-live.ts` is the core hook for the map screen: loads session/members, opens the realtime channel (`session:<id>` broadcast: `location`, `session`, `members` events; locations are never stored), watches the user's position with `expo-location` (foreground only, throttled to one broadcast per 3 s, blurred if the privacy pref is off, skipped while paused) and exposes leader actions. Background location is not implemented.
- **Maps** (`src/components/map/`): `live-map.tsx` renders the schematic map without a key and otherwise lazily loads `google-live-map.tsx` (`react-native-maps`, Google provider), so demo mode and an old dev build never touch the native map module; `live-map.web.tsx` always uses the schematic one. Place search, routes and pin naming are plain `fetch` to Google in `src/lib/maps-api.ts` (autocomplete returns names and distances; `resolveSuggestion` fetches the exact point with the `location` field only, the cheapest Place Details tier, and the same session token closes the billing session; routes use `TRAFFIC_UNAWARE`, switch `ROUTING_PREFERENCE` for live traffic at a higher price; Google maneuvers are mapped to the type/modifier names `lib/maneuver.ts` knows and a synthetic "arrive" step closes every leg). Names and turn instructions come back in Khmer when the app language is Khmer. `src/lib/geo.ts` holds distance/bounds/next-step helpers.
- **UI/theming**: `src/constants/theme.ts` is the single token source. The palette is copied from the Glidy web project (amber `#EFB708` on warm cream `#F9F6F0`, warm dark mode); semantic names are `primary` (amber), `primaryDark`, `accent` (soft amber tint), `backgroundElement` (cards), `backgroundSelected`, `ink`/`onInk` (the black pill tab bar and ink tiles), plus `Spacing` and `Radius`. Use `useTheme()` and the primitives in `src/components/ui/` (`Button`, `Card`/`IconBadge`/`ListRow`, `Screen`, `TextField`, `Icon`, `Avatar`, `Logo`, `LanguageToggle`). Visual reference is the "waypath" mock: rounded cards, round amber icon badges, outlined arrow buttons, floating black tab pill.
- **Brand identity and art** (`ui/brand-art.tsx`): Glidy's look is built on one motif, a dotted route line from a start dot to a pin. `LogoMark` (the logo), `RouteMotif` (hero-card decoration), `EmptyArt` (empty states) and `RouteThumb` (each trip drawn from its real geometry, used by `ui/trip-card.tsx` on Home and the Routes tab) are all `react-native-svg` and follow the theme. Use the `line` theme token, not `ink`, for strokes drawn on a soft `accent` tile: `ink` is near-black and disappears on the dark-mode tile, `line` turns amber there. Headlines use `ThemedText type="display"`: Exo 2 800 in English and **Moul** (the ornate Khmer headline face from the web project, single weight, very wide) in Khmer, drawn at 62% of the size to fit the same space. Digits and other text that should not change with language pass `fontLanguage="en"`. The Home hero card is the one big amber call to action; keep screens to one such moment. Quieter screens (sign-in, sign-up, create, join, invite, plan route, Menu, group ended) open with `ui/screen-hero.tsx` (`ScreenHero`: amber card, `display` headline, a faint `RouteMotif`; `leading` slot for an avatar). Numbers go on `ui/stat-strip.tsx` (`StatStrip`), which splits "1.8 km" so digits stay big and Latin (`fontLanguage="en"`) and the unit is small text in the app language.
- **Icons**: Lucide only (`lucide-react-native`). `Icon` takes a Lucide component (`<Icon icon={MapPin} />`); there are no SF Symbols or Material names anymore.
- **Fonts**: Exo 2 for English and Kantumruy Pro for Khmer (same pairing as the web project), loaded in the root layout with `useFonts` from `@expo-google-fonts/*`. Native fonts have one family per weight, so never set `fontWeight` on text yourself: `ThemedText` (and `TextField`) map `fontWeight` to the right family via `fontFamilyFor(language, weight)` and add extra line height for Khmer. Use `ThemedText`, not bare `Text`.
- **Tabs and liquid glass**: `(app)/(tabs)/_layout.tsx` is a custom floating pill built on `expo-router/ui` (`Tabs`/`TabList`/`TabTrigger`), not `NativeTabs`, so it can use Lucide icons. The pill, the round buttons and the title pill over the map use `<Glass>` (`src/components/ui/glass.tsx`), a wrapper around `expo-glass-effect`'s `GlassView`: real iOS 26 liquid glass where `hasLiquidGlass` is true, a solid surface (`fallbackColor`, black `ink` for the tab bar) on Android and older iOS. Icon colours on glass use the theme `text` colour; on the fallback they use `onInk`. A new tab needs a screen file and a `TabTrigger` there. Native Stack headers on modals already get the system glass on iOS 26.
- **Route map**: the saved-route page embeds the map in a scrolling page; a finger on the map freezes the page scroll (`Screen scrollEnabled`) so drags pan the map, and a glass maximize button opens `routes/map` (full-screen modal, `?id=`) where every gesture works: pan, pinch zoom, two-finger rotate and tilt (all enabled explicitly on `MapView`). Re-centre (`setCamera` with bounds, heading 0, pitch 0) refits the route and levels the map north-up.
- **Live session screen** (`session/[id].tsx`): the map fills the screen; `ui/bottom-sheet.tsx` is a draggable three-snap sheet (peek / half / full) built on RNGH 3 `usePanGesture` + Reanimated (UI-thread shared values; `scheduleOnRN` reports the settled snap back to React). Only the header drags; the body scrolls only at the full snap. A glass "full screen" button hides the sheet and the top bar (immersive: map + turn banner only). Floating map buttons ride on top of the sheet and fade out at the full snap. "Follow me" re-centres on every GPS update and switches off when the user touches the map. ETA and distance-left come from `routeProgress`/`distanceLeft` in `lib/geo.ts` (measured along the route, not as the crow flies). The map's top margin is the measured height of the top overlay (`onLayout`), because the turn banner grows when an instruction wraps.
- **Drive mode** (`session/[id].tsx` + `hooks/use-drive-navigation.ts`, `use-heading.ts`): "Start driving" turns the screen into a navigation view: heading-up camera tilted 55° and zoomed by speed (`zoomForSpeed`), shifted ahead of the arrow so it sits in the lower third (computed in `google-live-map.tsx` with `offsetAhead`/`metersPerPoint` and `mapPadding`); the sheet and top bar are hidden, a large turn banner (`nav-banner.tsx`, icon from `lib/maneuver.ts`) and a `DriveBar` (arrival, remaining, km/h, End) take over; the screen stays awake (`expo-keep-awake`, tag `glidy-drive`). Touching the map releases the camera until Re-centre. Route maths lives in `lib/geo.ts`: `snapToRoute` (per segment), `nextTurn` (distance measured *along* the route to the next manoeuvre, from `stepAnchors`), `routeProgress`. The part of the route behind you is drawn grey (`routeSnap`). Leaving the route by more than 60 m for 4 s triggers a **personal** reroute from the traveller's position (`getRoute`); it never changes the group's route and is dropped when the leader changes it. Google starts the new route at the nearest road, so `startingFrom` prepends a connector from the traveller's position; without it they would stay "off route" and be rerouted forever. Arrival (< 40 m left) opens `session/arrival-screen.tsx` over the map: confetti (Reanimated, one `Piece` per shared values, three falls then idle, skipped with `useReducedMotion`), a pin that drops and pulses, trip distance and time (`StatStrip`), who in the group is within 60 m of the destination, and Save route (leader) / Done. Trip time is measured to the moment the screen mounts from `driveStartedAt`; Done calls `endDriving`. Only foreground location exists, so the screen must stay on; background location is not implemented.
- **State updated while rendering must be idempotent**: `useHeading` and the old nav banner set state during render. Key such updates on the identity of the new input (a new GPS fix), never on "the smoothed value differs": smoothing again on every render never settles and crashes with "Too many re-renders".
- **Testing a drive in the iOS simulator**: `xcrun simctl location <udid> start --speed=20 lat,lng lat,lng …` plays waypoints at a speed (feed it points from a Google route); `set lat,lng` jumps. A Fast Refresh resets screen state, so re-enter drive mode after editing code.
- **Map padding**: `GoogleLiveMap` passes the overlays as `mapPadding` (top bar and turn banner, bottom sheet), which keeps the Google logo visible and makes the camera's middle the middle of the free area; fit margins are therefore small. Drive mode shifts the centre ahead by a fifth of that area. Zoom helpers (`zoomForSpeed`, `metersPerPoint`) are in 512 px tile zoom; `toGoogleZoom` adds 1 for Google.
- **Drive arrow**: `map/drive-arrow.tsx` is a top-down faceted SVG arrow used as a *flat* marker with `rotation={heading}` (an absolute bearing). Flat markers turn with the map, so with the tilted heading-up camera it lies on the road in perspective; do not also rotate the view with CSS (that double-counts and made the old arrow point the wrong way).
- **Leader**: the leader owns the route; their avatar wears a crown (`Avatar leader`, used by the map markers and member lists; custom map markers get padding so the crown is not clipped by the marker bitmap). Handing over: `Backend.sessions.transferLeader` calls the `transfer_leadership` SQL function (`supabase/schema.sql`, `migrations/002_transfer_leadership.sql`, SECURITY DEFINER because the leader's own UPDATE policy cannot change `leader_id`). Asking: a member's `requestLeadership` broadcasts `leader-request` on the session channel (nothing is stored); only the current leader's phone shows the accept/decline card, and `leader-declined` answers just the asker. `useSessionLive.applySession` is the single place that notices a leader change and raises the notice. In demo mode `mock-backend` simulates a traveller asking about 20 s in and the leader accepting your ask after 2.5 s. The decision card and notices render in the `alerts` overlay above the bottom sheet. Run `002_transfer_leadership.sql` on an existing Supabase project before using hand-over.
- **Dialogs**: never call `Alert.alert` (the system alert ignores the app's fonts, colours and Khmer). `ui/dialog.tsx` has `DialogProvider` (mounted in the root layout) and `useDialog().confirm({ title, body, confirmLabel, cancelLabel, destructive, icon })`, which resolves `true`/`false`; `cancelLabel: null` makes it a one-button notice. `destructive` draws the confirm button in the filled red `Button` variant `destructive`.
- **Stops along the route**: `remainingStops`/`stopIndices` in `lib/geo.ts` place each stop at the vertex where its leg ends (the leg's `arrive` step, i.e. where the router snapped the stop onto the road), searching forward from the previous stop. Using the vertex nearest the stop's raw point was wrong for stops in the middle of a roundabout or on a loop, where the nearest vertex is on the far side and the stop is never counted as passed. The "Stop N reached" toast and the reroute that keeps only upcoming stops both rely on this.
- **Map style changes**: the dark theme is the `GOOGLE_DARK_STYLE` array passed as `customMapStyle` (plus `userInterfaceStyle`), so a theme flip updates the map in place with no remount. Custom marker views are drawn through `TrackedMarker`, which tracks view changes for a moment (avatar images load late) and then stops, to keep many markers cheap.
- **i18n (English + Khmer)**: `src/i18n/en.ts` defines every key; `km.ts` is typed `Record<TranslationKey, string>`, so a missing Khmer string fails `tsc`. In components use `const { t } = useI18n()` (never import the bare `t` in UI: `useI18n().t` changes identity per language, which is what makes React Compiler-memoised text update on a switch). The bare `t` from `@/i18n` is for the data layer and formatters (`formatDistance`/`formatDuration`). The language is stored under `glidy.language.v1`, defaulting to the device language (`expo-localization`, loaded lazily so an older dev build without the native module falls back to English). Turn instructions and place names come from Google in the app language (Khmer included).
- **Menu and settings**: the third tab (`(app)/(tabs)/profile.tsx`, labelled "Menu") is a menu: avatar and name, a "Settings" group (Edit profile, Display, Language, Privacy) and a "Help & info" group (About, Contact us), then Log out. Each row opens a screen under `(app)/settings/` (registered in `(app)/_layout.tsx`). Build menus with `MenuGroup`/`MenuRow` (`ui/menu-row.tsx`) and choices with `Segmented` (`ui/segmented.tsx`).
- **Display settings** (`hooks/use-settings.ts`, persisted under `glidy.settings.v1`): *Text size* (Default 1x, Large 1.15x, Extra large 1.3x) is applied by `ThemedText`/`TextField` through `scaleText` (sizes of 32 and up grow only half as much). Anything with a fixed height must follow it: the trip sheet's peek height and the drive bar scale with `useTextScale()`, and long labels wrap (`numberOfLines={2}`) or shrink (`adjustsFontSizeToFit`) rather than clip. Do not hard-code font sizes on bare `Text`. *Appearance* (System/Light/Dark) calls React Native's `Appearance.setColorScheme` (`'auto'` = follow the system in this RN version), so `useColorScheme()`, headers, alerts, glass and the map style all follow it with no per-component code.
- **Profile pictures** (`lib/avatar.ts`, `lib/avatar-photo.ts`, `ui/avatar.tsx`, `settings/account.tsx`): an `Avatar` is `{kind:'emoji', emoji, color}` or `{kind:'photo', uri}` (a 192 px square JPEG as a `data:` URI, ~8 KB), or null for initials. A photo is picked with `expo-image-picker` (square crop UI), shrunk with `expo-image-manipulator` and stored in the profile row itself, so no file storage is needed. It lives in `profiles.avatar` (jsonb) and NOT in the auth user metadata (metadata is in the JWT sent with every request). Members get it through the `session_members -> profiles` join; map markers get a `{userId: avatar}` record (`avatars` prop of `LiveMap`). Anything read from the database goes through `parseAvatar`, which only accepts an emoji on a hex colour or a small base64 JPEG, because other people's avatars are untrusted input. `supabase/migrations/001_profile_avatar.sql` adds the column; until it is run the Supabase backend still works (it detects the missing column and shows initials) and saving a picture says it is not set up yet. The iOS Simulator has no camera: `launchCameraAsync` throws there and the app reports it as unavailable.
- **Links and contact** (`constants/links.ts`): the privacy policy opens `https://glidy.app/privacy` in an in-app browser (`expo-web-browser`). The Contact screen's email, Telegram and Facebook values are PLACEHOLDERS that must be replaced before release.
- **Place search is its own screen**: `PlaceSearch` (`components/session/place-search.tsx`) is only the tappable field; it opens `place/search.tsx` (full-screen modal, result bus key `search-place` via `lib/place-picker.ts`), which hosts `PlaceSearchPanel` (`place-search-panel.tsx`: the real input, recents, Google results, "Choose on map"). The input is pinned at the top with a back arrow so the keyboard never covers results. `autoFocus` on the field opens the screen straight away.
- **Choosing places and routes**: every destination search (`PlaceSearch`, with `mapPick`) offers "Choose on map", which opens `place/pick.tsx` (full-screen modal: `components/map/pick-map.tsx` under a fixed pin in its own box above the panel, `reversePlace` names the centre once the map is idle). The leader's "Route and stops" tile opens `route/edit.tsx`: start (phone position), up to `MAX_STOPS` (8) stops that can be reordered/removed, the destination, and Google alternatives (only when there are no stops; the API does not offer them with stops). Both screens are opened as promises through `lib/screen-results.ts` (`openForResult`/`payloadOf`/`finish`; wrappers `lib/place-picker.ts`, `lib/route-editor.ts`) because Expo Router params cannot carry objects; each screen calls `finish(key, null)` from its unmount so the promise always settles. Stops are stored on `Route.stops` (inside the existing jsonb), so no schema change; `planRoutes` builds the route, `getRoute` is the two-point wrapper. Drive mode keeps `remainingStops` when it reroutes, and the saved-route "trip home" visits the stops in reverse. Stops are drawn with `map/stop-badge.tsx` (numbers stay Latin).
- **Imports**: `@/*` → `src/*`; `@/assets/*` → root `assets/`.
